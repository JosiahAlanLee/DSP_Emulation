# Adapter

ByteBusLab 2.17, 16 HP. Explicit byte-format conversion, bit routing and
reclocking between Gorgon, CZish/DAC Stage and the Harriot modules. The
[carrier](../../../docs/BYTE_BUS_SPEC.md) is unchanged. The cable carries no
format metadata: choose its meaning on the panel, or use a preset.

## Formats

INPUT and OUTPUT select these formats independently:

| Format | Meaning |
|---|---|
| Offset / raw | Standard offset binary: 80 is zero, 00 is -1, FF is 127/128. With both selectors here, every byte is passed exactly, including flags and addresses. |
| Signed linear | The high eight bits of a signed two's-complement DAC word. Conversion to/from Offset is exactly XOR 80. |
| CZ encoded | Bits 13-6 of CZish/DAC Stage's provisional 14-bit word: two range bits and six mantissa bits. |
| YM encoded | Bits 12-5 of DAC Stage's 13-bit Yamaha word: exponent, sign and high mantissa bits. |

Identical formats preserve every input byte exactly. Other pairs decode to
signed 16-bit PCM, then encode the destination format using the shared DAC
quantizers. Missing low device-word bits are filled with zero. CZ range 3
decodes as range 2, matching DAC Stage. CZ TRACK in the context menu matches
the source's tracking error (-50 to +50 percent); it affects CZ decoding.
Encoding CZ uses the instantaneous model, not a reconstructed syllabic envelope.

Silence examples: CZ 00 -> Offset 80; YM 30 -> Offset 80; Signed 00 -> Offset
80. Offset 80 -> Signed 00 or CZ 00 or YM 30. These are software-model
conversions, not a claim that the provisional CZ word is a physical chip bus.
Discarded low bits and skipped device samples cannot be recovered. The native
audio output remains the path for the full signal.

Open `examples/adapter-cz-audio.vcv` for a native-left / decoded-bus-right
comparison using DAC Stage's CZ profile; select an audio device after loading.
`examples/adapter-repeated-triggers.vcv` holds word 41 in a Register at 8 Hz:
the first Split shows held lane 1, the second shows repeated lane-1 triggers,
and FILL (bit 6) is removed. Both patches are generated by
`tools/make_adapter_patches.py` and exercised in the Rack API tests.

## Routing and outputs

On acquisition, Adapter converts the byte, routes its bits, then applies
`output = (routed & KEEP) XOR XOR`. Each output bit chooses input bit 0-7 or
Off in the context menu; routing is after format conversion. Repeated sources
are allowed. KEEP and XOR are byte knobs, not audio gains. Off followed by XOR
can make a constant high bit. The default mapping is identity, KEEP=FF, XOR=00.

| Output | Meaning |
|---|---|
| BUS | Final byte, 8 channels in Engine mode, otherwise 9 with publication CLK. |
| CLK | Same one-engine-sample publication strobes as BUS channel 9; zero in Engine mode. |
| GATES | Eight polyphonic 0/10 V bit levels, held with the final byte. No clock channel. |
| TRIG | Eight polyphonic one-engine-sample triggers. Clocked acquisitions retrigger each set bit even if the byte repeats. Engine mode triggers only bits that rise. |
| BIPOLAR | Raw final byte interpreted as `(word-128)*5/128` V. Choose OUTPUT=Offset for a decoded waveform. |
| LEVEL | Raw final byte interpreted as `word*10/255` V for a unipolar control or address. |

TRIG is silent on seed publications and while BUS IN is disconnected. A fresh
Engine connection seeds its bit detectors on the first acquisition; held
levels do not produce hot-plug hits. These are Rack sample pulses, not hardware
trigger guarantees. A downstream Tracks input can consume TRIG directly; a Bus
input can consume BUS. Do not connect the nine-channel BUS to a Tracks input.

## Clocks, startup and reset

Adapter is a latching converter. It regenerates publication strobes rather than
forwarding an incoming clock's duty cycle. It uses the shared ClockOwner rules:

| SOURCE | Acquisition |
|---|---|
| Follow bus | BUS CLK edges for 9+ input channels; Engine rate for 1-8 channels. A connected stopped bus clock holds indefinitely. |
| CLOCK jack | Current raw data lines on CLOCK rising edges, even if BUS IN has its own stopped clock. A missing CLOCK stays stopped. |
| Internal | Current raw data at RATE, 0.125-2048 Hz, independent of BUS CLK. |
| Engine | Current raw data every Rack sample, emitting eight channels without CLK. |

RATE only controls Internal. CZish at 48 kHz publishes about 20,000 words/s;
select Internal to sample it slowly for frame addresses, masks or control.
There is no timeout fallback. CLOCK and RESET use 1 V/0.1 V Schmitt thresholds;
all clock detectors keep tracking while unselected. Switching sources does
not invent an edge on an already-tracked high clock.

Fresh instances, Initialize, patch restore, connection/disconnection and
changes between clocked/unclocked input modes start with IDLE (00 by default).
The initial sample publishes IDLE and consumes an already-high clock without
acquiring. RESET or LOAD loads IDLE, restarts the internal phase and publishes
it, even if the acquisition clock is stopped. Held RESET does not keep loading.
TRIG stays silent for these publications. Changing IDLE alone applies on the
next load or acquisition without BUS IN.

Clocked strobes always have a low sample between them. A load immediately
after a high waits through a low sample; the seed is already loaded. Nearby
acquisition edges are suppressed, as in Register. Each cable hop adds one Rack
sample. Parameter/routing edits take effect on the next acquisition, not during
a held word. A source change rearms Engine trigger detection.

Controls and bit routes save with the patch; held words, fractional clock
phase and input detectors do not. Reload starts from IDLE. Presets restore all
adapter controls/routes and restart this transient state.

## Presets and pairings

Presets are in the context menu. Select one before patching audio outputs:

- **Raw byte relay**: identity, Follow, idle 00. Addresses, masks, ratio words
  and other packed fields retain every bit; their destination still defines meaning.
- **CZish / CZ DAC -> standard audio**: CZ to Offset, Follow, idle 80.
- **Yamaha DAC -> standard audio**: YM to Offset, Follow, idle 80.
- **Linear DAC -> standard audio**: Signed to Offset, Follow, idle 80.
- **Standard -> CZ encoded word** and **Standard -> Yamaha encoded word**:
  quantize a standard byte to the selected truncated device format.
- **Gorgon hits -> drum triggers**: KEEP=3F removes FILL and reserved bit 7.
  Send TRIG to Machinemodule Tracks, or BUS to its Bus mode. This transports
  hits only; pitch, velocity and sound locks use their existing paths.
- **Active lanes -> Gorgon mutes**: KEEP=7F, XOR=3F inverts lane bits 0-5,
  preserves FILL on bit 6 and clears reserved bit 7. Gorgon's saved score
  mutes still merge by OR, so a bus cannot unmute a score-muted lane.
- **Slow address / mask sampler**: raw bytes, Internal at 8 Hz, idle 00.
  Useful between an audio-rate source and OTIS FRAME BUS or Seance MASK IN.
  OTIS still owns playback and its optional frame smoothing; Seance still
  samples its mask per spectral frame and applies its own slew.
- **Centered control -> XOR mask**: Offset to Signed, so input 80 gives mask
  00. It produces a bit mask for XOR BUS, not a new audio input to CZish.

For standard audio, CZish BUS -> Adapter (CZ preset) -> Converter BUS or
Vastish BUS A. Adapter BIPOLAR can also go straight to an ordinary audio/CV
input. CZish's original divided publication rate and analog-filter delay are
not removed. Raw encoded words remain available by selecting the relay preset.

## Validation

Portable tests exhaust byte conversions and routing, check known silence and
polarity values independently, and exercise frozen clocks, raw reclocking,
repeated words, reset/low gaps, lifecycle and triggers at 44.1/48/96 kHz. Rack
API tests connect the actual CZish/DAC Stage, Adapter, Converter, Vastish and
OTIS modules through delayed cables; Gorgon hit masks and the Seance mask
consumer are checked against their contracts. The processing path allocates
no memory. These tests do not validate physical interfaces, manufacturer
firmware or a live desktop.
